Feature 3 · Domain / Website Trust RULE R18

Koi bhi request — link, SMS, WhatsApp message, QR ke peeche ka page, ya screenshot me dikha domain — usko 4-level ladder par rakha jaata hai. Chahe payment gateway legit ho (Razorpay/PayU/Cashfree/BillDesk), agar merchant ka domain verified nahi hai to warning milti hai. Kyunki "gateway achha hai" ka matlab "merchant achha hai" nahi hota — ye classic 2026 trick hai.

4-LEVEL LADDER
✓L1 · Verified (RBI/NPCI/bank/PSP registry)
✓L2 · Verified merchant (allowlist)
!L3 · Unverified but clean → amber warning
✕L4 · Lookalike / fake → red warning
HEURISTICS (production me + RDAP age, FRI, registry)
homoglyph (0↔o, 1↔l, rn↔m) · typosquat distance ≤2 · brand-in-subdomain (sbi.secure-login.xyz) · punycode xn-- · risky TLD (.xyz .top .online .click .icu .buzz .cf .tk) · URL shortener · no HTTPS · IP-literal host · @ in URL · gateway-merchant mismatch · domain age < 90 din · FRI/I4C hit
Wording principle (deck se): unknown-clean domain par hum “scam” nahi likhte — “verified nahi hai, dhyaan se” likhte hain. Red sirf tab jab structural proof ho (lookalike/TLD/no-TLS/shortener).

SEBI / NSDL registry check RULE R26

“SEBI-registered” ka dawa sabse aam trick hai. Hum teen cheezein check karte hain: (1) registration-number ka format (INZ/INH/INA + 9 digits), (2) official portal domains (sebi.gov.in · scores.gov.in · smartodr.in · nsdl.co.in), (3) debarred-entity naam. Number valid bhi ho to hum “verified” nahi kehte — sebi.gov.in par khud check karo link dete hain.
