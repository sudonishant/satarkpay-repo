The limits, stated before anyone asks

A browser cannot read your SMS. Nothing in this web build can see an incoming message on its own — you paste it. That is a platform boundary, not an oversight.
Rules can be read and walked around. Any published rule set can be studied by the people it is meant to catch. The defence is that the rules are only one signal of nine — the chain survives a rule being dodged.
A clean domain is not a safe domain. This build never contacts the network, so it cannot know how old a domain is or what it is serving today.
No name verification. The single most useful check in Indian payments is whether the payee name your app displays matches the name you were told. That lookup belongs to the PSP and is not available to an app. Without it, "verify the name" stays a manual step — which is why the app keeps telling you to do it.
On SEBI's own record advice: the check that an entity is registered does not by itself establish that a particular transaction or product is legitimate. Registration is a starting filter, not a verdict — so this app presents it as a step to take, not a result to trust.
What would actually fix this at scale is not a better classifier. It is the signal chain running inside the payment app, where the context already exists, with the payee name lookup made available to it. That needs a PSP to say yes.

Build

Static files, no framework, no build step, no dependencies, no network calls. Eight pages, one stylesheet, three JavaScript files (engine.js, chain.js, data.js) and a service worker that precaches the whole shell. Open index.html and it works — from a file, from a server, or with the network switched off.
